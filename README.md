# LMS Django REST Framework Project

Бэкенд-сервер для платформы онлайн-обучения (LMS-системы).
---

## Стек технологий

- Python 3
- Django / Django REST Framework (DRF)
- PyJWT / Django REST Framework Simple JWT
- PostgreSQL
- Django-filter (для фильтрации API)
- Инструменты качества кода и тестирования: Black, Flake8, Coverage
- **drf-yasg** (Автоматическая документация Swagger/ReDoc)
- **Stripe API** (Интеграция онлайн-платежей)
- **Celery & Celery Beat** (Асинхронные уведомления и периодические задачи)
- **Redis** (Брокер сообщений)

---

## Как запустить проект

1. Клонировать репозиторий.
2. Создать файл `.env` в корне проекта и заполнить его переменными (включая настройки Redis):
   ```env
   SECRET_KEY=твой_секретного_ключ
   DB_PASSWORD=твой_пароль_от_postgres
   STRIPE_SECRET_KEY=твой_секретный_тестовый_ключ_stripe_(sk_test_...)
   CELERY_BROKER_URL=redis://127.0.0.1:6379/0
   CELERY_RESULT_BACKEND=redis://127.0.0.1:6379/0
   ```
3. Установить зависимости:
   ```bash
   pip install -r requirements.txt
   ```
4. Применить миграции:
   ```bash
   python manage.py makemigrations
   python manage.py migrate
   ```
5. **Загрузить группы пользователей и тестовые демонстрационные данные из фикстур**:
   ```bash
   python manage.py loaddata users/fixtures/groups.json
   python manage.py loaddata base_data.json payments_data.json
   ```
6. **Запуск тестов и замер покрытия** (опционально):
   ```bash
   coverage run --source='.' manage.py test
   coverage report
   ```
7. Убедиться, что сервер **Redis** запущен локально на порту `6379`.
8. Запустить **Celery Worker** (в отдельном терминале):
   ```bash
   celery -A config worker -l info -P threads
   ```
9. Запустить **Celery Beat** (в отдельном терминале для отслеживания расписания):
   ```bash
   celery -A config beat -l info
   ```
10. Запустить основной сервер Django:
    ```bash
    python manage.py runserver
    ```

## Документация API

После запуска сервера интерактивная документация доступна по адресам:
* **Swagger UI**: [http://localhost:8000/swagger/](http://localhost:8000/swagger/) — тестирование эндпоинтов из браузера.
* **ReDoc**: [http://localhost:8000/redoc/](http://localhost:8000/redoc/) — удобный формат для чтения схем.

> **Инструкция по авторизации**: Получите JWT-токен на эндпоинте `POST /api/token/`. Нажмите кнопку **Authorize** в правом верхнем углу Swagger и введите токен в формате: `Bearer <ваш_токен>`.

## Интеграция со Stripe (Платежи)

В проекте реализован изолированный сервисный слой (`services.py`) для работы с эквайрингом Stripe.

### Реализованные эндпоинты:
1. **`POST /users/payments/create/`** — Создание платежа. Регистрирует продукт/цену в Stripe, создаёт сессию Checkout, возвращает пользователю ссылку на оплату (`payment_link`) и сохраняет `session_id`.
2. **`GET /users/payments/<int:pk>/status/`** — Проверка статуса оплаты (Дополнительное задание ⭐). Запрашивает данные сессии из Stripe API и автоматически синхронизирует статус (`paid`/`unpaid`) в локальной базе данных.

### Тестирование оплаты
Для проверки успешного прохождения транзакции по ссылке `payment_link` используйте стандартную тестовую карту Stripe: `4242 4242 4242 4242` (с любым CVC и будущим сроком действия).

## Валидация, Подписки, Пагинация и Тестирование

- **Валидация контента**: Добавлен кастомный валидатор для проверки входящих URL-ссылок на уроки. Система строго блокирует любые сторонние ресурсы, разрешая прикреплять видеоматериалы исключительно с домена `youtube.com`.
- **Подписки на обновления**: Реализована полноценная Toggle-логика подписок для пользователей на обновления интересующих их курсов. Если подписки нет — эндпоинт её создает, если есть — удаляет. Ограничение на уникальность пары «пользователь-курс» гарантировано на уровне базы данных (`unique_together`).
- **Динамический признак подписки**: В сериализатор курсов внедрено поле `is_subscribed` на базе `SerializerMethodField()`, которое на лету сообщает текущему авторизованному пользователю, подписан ли он на конкретный курс.
- **Кастомная пагинация**: Создан собственный класс пагинации `CustomPaginator` для порционного вывода списков курсов и уроков. Заданы параметры `page_size`, `page_size_query_param` для динамического изменения размера страницы клиентом и `max_page_size` для защиты от перегрузки сервера.
- **Автоматизированное тестирование (CRUD & Permissions)**: Написан расширенный пакет тестов на базе `APITestCase`. Полностью протестирован весь CRUD-цикл уроков, логика создания/удаления подписок, а также разграничение прав доступа для обычных пользователей и модераторов.
- **Контроль покрытия кода**: В проект внедрена утилита `coverage`. Код ключевых модулей приложения полностью протестирован, сгенерирован и сохранен итоговый отчет `coverage.txt`.

## 🛠 Предыдущие обновления (Авторизация и Права доступа)

- **Кастомная авторизация и JWT**: Вход в систему реализован по полю `email` вместо стандартного `username` с использованием JWT-токенов (`Simple JWT`). Все эндпоинты проекта закрыты авторизацией.
- **Роли и Группы (Модераторы)**: Реализована группа модераторов (`moderators`). Модераторы имеют право просматривать и редактировать любые курсы и уроки, но ограничены в правах на создание и удаление объектов.
- **Права Владельцев (IsOwner)**: Обычные пользователи (не входящие в группу модераторов) имеют доступ на просмотр, изменение и удаление только тех курсов и уроков, которые они создали сами.
- **Автозаполнение авторов**: При создании курса или урока через API поле владельца (`owner`) автоматически заполняется текущим авторизованным пользователем.
- **Ограничения профилей**: Авторизованные пользователи могут просматривать чужие профили в урезанном виде (без платежей и паролей), а редактировать — только свой собственный.
- **Подсчет данных**: В эндпоинт курсов добавлено автоматическое вычисление количества связанных уроков (`lessons_count`).
- **Вложенная структура**: При просмотре курсов данные уроков разворачиваются автоматически.
- **Гибкая фильтрация**: Реализован эндпоинт платежей с возможностью фильтрации по курсу, уроку, способу оплаты и сортировкой по дате.

## Реализованные фоновые задачи (Celery)

1. **Асинхронная рассылка (по событию):** Метод `perform_update` в `CourseViewSet` вызывает задачу `send_course_update_email` при редактировании курса. Письма отправляются всем подписчикам, если с момента последнего изменения прошло более 4 часов.
2. **Периодическая задача (по расписанию):** Планировщик Celery Beat раз в сутки запускает задачу `check_inactive_users`. Она фильтрует пользователей по полю `last_login` и блокирует аккаунты (`is_active = False`), если они не проявляли активность более месяца. Обновление записей оптимизировано и выполняется **батч-запросом**.
